01-basics · A szerverállapot megjelenítése

A saját .NET 8-as vagy .NET 10-es vázadba építs health ellenőrzést. Kövesd a kérés útját a WPF ablaktól a Web API-ig és vissza.

Lépésenkénti segítség a bal oldali menüs útmutatóban · Másolható feladatlap és ellenőrzőlista

Haladj a fejezet rövid feladatleírásából. Ha elakadsz, nyisd meg az adott lépés útmutatóját, majd ott a Mit nézz meg a kész mintában? részt. A saját projektedben ellenőrizd a működést.

A rétegek feladata

  1. Közös DTO és Web API

    Lépésenkénti segítség

    A MyApp.Shared projektben a HealthResponse adja a válasz alakját. A HealthController töltse ki a Status mezőt a GET /api/health kérésre. Próbáld ki a végpontot a kliens indítása előtt.

  2. Kliensoldali API service

    Lépésenkénti segítség

    A HealthApiService alapcímét egyeztesd a Web API http profiljával. Olvasd be a JSON-t HealthResponse típusba, és adj kezelhető hibát a ViewModelnek.

  3. ViewModel és WPF nézet

    Lépésenkénti segítség

    A HealthViewModel kezelje a három állapotot. Állítsd be az ablak DataContext értékét. Kösd a feliratot, a jelzést és az Újrapróbálás gombot, és indítsd az ellenőrzést betöltéskor.

Ellenőrzés

Ellenőrzés a menüs útmutatóban

  1. Indítsd külön a Web API-t és a WPF klienst. Ellenőrizd, hogy ugyanazt a címet használják.
  2. Hasonlítsd össze a futó és a leállított szerverhez tartozó feliratot. Indítsd vissza a szervert, és kattints az Újrapróbálás gombra.
  3. Mutasd meg a válasz útját a DTO-tól a WPF-kötésig.
