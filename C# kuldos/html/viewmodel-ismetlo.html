Az 01-es tanári bemutató és a 02-es önálló munka előtt járd végig ezt az összefoglalót. A próbákat saját gyakorlóprojektben vagy a másolt diákpéldányban végezd. A minták az összefüggéseket mutatják, a konkrét neveket mindig a kész felületből és a service-szerződésből olvasd ki.

1. A mezőből a felület által figyelt property lesz

Az ObservableObject változásértesítést ad. A partial osztályban az ObservableProperty attribútum hatására a Community Toolkit fordításkor létrehozza a publikus propertyt. A XAML ehhez kötődik, ezért a műveletekben ezt állítsd.

[ObservableProperty]
private string description = string.Empty;

// A műveletben a generált publikus property változik.
Description = string.Empty;

A Description a felhasználó adatát tárolja. A StatusMessage, HasError és IsBusy a felület visszajelzéseit vezérli. A backendnek a kérés DTO-jában meghatározott adatokat küldjük.

Kis próba. Egy kötött szövegmezőben adj új értéket a generált propertynek egy gomb hatására. Figyeld meg a feliratot. Miért nem a privát mezőt állítjuk?

2. A metódusból parancs lesz

private bool CanSubmit() => !IsBusy;

[RelayCommand(CanExecute = nameof(CanSubmit))]
private async Task SubmitAsync()
{
    // A művelet helye.
}

A SubmitAsync metódusból SubmitCommand keletkezik. Ezt köti a gomb Command tulajdonsága. A CanExecute azt mondja meg, mikor indítható a parancs. Az IsBusy változásakor kérni kell az engedélyezési feltétel újraértékelését.

[ObservableProperty]
[NotifyCanExecuteChangedFor(nameof(SubmitCommand))]
private bool isBusy;

Kis próba. Vizsgáld meg, mi történik a gombbal IsBusy igaz, majd hamis értékénél. Mondd el külön a RelayCommand és a NotifyCanExecuteChangedFor szerepét.

3. Egy sor gombja a sor adatát adja át

A listában több Lezárás gomb van. A CommandParameter adja át, melyik rekordhoz tartozó gombot nyomták meg. A WPF mintában a gomb parancskötése a szülő ViewModelre mutat, a paraméterkötés a sor objektumát adja.

private bool CanClose(ReportResponse? report) =>
    !IsBusy && report is { IsClosed: false };

A kérdőjel azt jelzi, hogy a paraméter null is lehet. A feltétel csak létező, nyitott rekordnál ad igazat. A metódus elején is védd a műveletet. A mintában később használt report! a fordító figyelmeztetését kezeli, a nullérték futásidejű ellenőrzését a korábbi feltétel végzi.

Kis próba. Az 01-es admin XAML-ben keresd meg a Command és CommandParameter kötést. Magyarázd el, miért a rekord Id mezőjét kapja az API. Admin WPF-nézet · .NET 10 · .NET 8

4. Az API-hívás alatt a felület állapotot jelez

A konstruktorban kapott service már rendelkezésre áll. Az await megvárja az aszinkron művelet eredményét. A try sikeres ágában kezeld az eredményt, a catch ágakban a hibát. A finally mindkét esetben visszaállítja a várakozási jelzőt.

if (IsBusy) return;

try
{
    IsBusy = true;
    HasError = false;
    // var result = await ...;
    // A mezők és az üzenet sikeres frissítése.
}
catch (ApiException exception)
{
    HasError = true;
    StatusMessage = exception.Message;
}
catch (Exception exception)
{
    HasError = true;
    StatusMessage = $"Nem sikerült kapcsolódni a backendhez: {exception.Message}";
}
finally
{
    IsBusy = false;
}

Kis próba. A tanári bemutatóban állítsátok le a backendet egy művelet előtt. Miért kell a finally akkor is, ha a kérés hibát dob? Hiba esetén miért marad meg a beírt adat?

5. Teljes lista és egyetlen sor frissítése

Az ObservableCollection jelzi a sorok hozzáadását, eltávolítását és cseréjét a felületnek. Betöltéskor a visszakapott teljes listából új kollekció készül. Egy lezárásnál viszont az Id alapján megkeresett elem cserélődik le a backend friss válaszára. Ez a sor állapotát és a sorhoz kötött gomb megjelenését is frissíti.

6. Egy adat változása több felületi értéket érinthet

A 02-esben a CurrentQuestion tárolja az aktuális kérdést. A HasQuestion ebből számolható, ezért külön értesítést igényel, ha a CurrentQuestion megváltozik. Az ugyanettől függő parancs engedélyezését is újra kell értékelni.

[ObservableProperty]
[NotifyPropertyChangedFor(nameof(HasQuestion))]
[NotifyCanExecuteChangedFor(nameof(SubmitAnswerCommand))]
private RandomQuestionResponse? currentQuestion;

public bool HasQuestion => CurrentQuestion is not null;

A NotifyPropertyChangedFor a számított felületi propertyt frissíti. A NotifyCanExecuteChangedFor a parancs használhatóságát értékeli újra. A 02-esben a HasAnswered további helyi állapot, amely a már beküldött válasz ismétlését tiltja.

Kis próba. Írd le, mit jelent a beküldésnél a három feltétel együtt — nincs folyamatban művelet, van kérdés, még nem válaszoltál. Mi történjen új kérdés betöltésekor?

A 04-esben a SubmissionStatus enum három elnevezett értéke segíti a szerverválasz értelmezését. Egy sikeres lekérés eredménye lehet függőben lévő vagy kitiltott beküldés is.
