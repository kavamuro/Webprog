Közös művelet kiemelése segédmetódusba

Ajánlott olvasmány a 04-es AdminSubmissionsViewModel elkészítése előtt. A jóváhagyás és a kitiltás külön metódusokban is megoldható. Ez a minta a közös lépések egy helyen történő megírását mutatja.

Melyik rész ismétlődne?

Mindkét művelet ellenőrzi a kiválasztott sort, várakozási állapotot állít be, meghívja az API-t, a válasz alapján lecseréli a lista érintett elemét, majd üzenetet ír. A hibakezelés és az IsBusy visszaállítása is azonos. Az API-művelet neve tér el.

Három metódus, két döntési lehetőség

Az ApproveAsync és a BanAsync a gombokhoz tartozó parancsmetódusok. A DecideAsync saját segédmetódus. A bool approve paraméter true értéke jóváhagyást, false értéke kitiltást jelent. A listabetöltés továbbra is külön művelet.

[RelayCommand(CanExecute = nameof(CanDecide))]
private Task ApproveAsync(StudentSubmissionResponse? submission)
    => DecideAsync(submission, approve: true);

[RelayCommand(CanExecute = nameof(CanDecide))]
private Task BanAsync(StudentSubmissionResponse? submission)
    => DecideAsync(submission, approve: false);

private async Task DecideAsync(
    StudentSubmissionResponse? submission,
    bool approve)
{
    // Ellenőrzés, várakozás, API-hívás, sorfrissítés és hibakezelés.
}

A két parancs Task eredménnyel továbbadja a közös aszinkron műveletet. A RelayCommand attribútumokkal létrejön az ApproveCommand és a BanCommand. A DecideAsync közvetlenül a két metódusból hívódik.

Hogyan töltsd ki a közös részt?

  1. Csak létező és Pending állapotú sor esetén kezdj műveletet. Ha IsBusy igaz, várj az aktuális művelet végéig.
  2. A try ágban állítsd be a felületi jelzőket. Az approve paraméter alapján az ApproveAsync vagy a BanAsync service-műveletet várd meg.
  3. Az eredmény Id mezőjével keresd meg a listában a korábbi elemet, és cseréld le a szerver válaszára.
  4. Az ismert catch ágakkal adj visszajelzést, a finally blokkban állítsd vissza az IsBusy értékét.
